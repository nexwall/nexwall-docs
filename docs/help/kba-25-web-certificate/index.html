KBA-0025: Web interface address and certificate

Applies to firmware 26.0.0-rc4 and later. Firmware up to rc3 uses a shared certificate for firewall.nexwall.com.br (see the last section).

What to type​

AddressResult
https://firewall.lan.nexwall.com.brthe web interface, with a certificate the browser trusts (no warning). This is the address on the label.
https://<serial>.lan.nexwall.com.brthe same, by the serial number of the unit in lower case, for example https://nxw-5391-a3b2-7c4c.lan.nexwall.com.br.
http://192.168.1.1 (or the LAN address you configured), http://firewall.lana small page that opens the trusted address, or shows the direct link if the computer cannot reach it.
https://192.168.1.1, https://firewall.lanthe web interface, but the browser warns about the certificate: no public authority issues certificates for private addresses. Accept the warning once or use the trusted address.

How it works​

  1. The firewall answers the two names above itself: its DNS server returns the LAN address of the unit. The computer must therefore use the firewall as its DNS server (the default when the computer gets its address from the firewall by DHCP).
  2. The unit makes a private key of its own (it never leaves the unit) and asks the Nexwall license server for a certificate for its two names. The server asks Let's Encrypt, which validates the names through DNS, and the unit installs the answer after checking the signature of the server, the names and its key.
  3. This starts a few minutes after the first registration with the license server (internet and a registered unit are needed) and is checked every 30 minutes; the certificate is renewed automatically 28 days before it ends (it is valid for 90 days).
  4. Until a valid certificate is installed, and whenever it stops being valid, the web interface keeps (or goes back to) its own self-signed certificate, so it is always reachable by the direct address.

Commands (on the firewall)​

Output of nexwall-webui-cert status, licensectl state and the serial number

CommandWhat it does
nexwall-webui-cert statuswhat is in use: using (nexwall or self-signed), valid, mode (unit = the certificate of this unit, shared = the shared one of older firmware, none), names, expiry (epoch seconds)
nexwall-webui-cert syncdo it now: DNS entries, then request/renew the certificate (up to about 2.5 minutes while the validation runs)
nexwall-webui-cert dnsonly the DNS entries (after the LAN address was changed)
nexwall-webui-cert revertback to the self-signed certificate
grep nexwall-webui-cert /var/log/messageswhat happened on the last runs

Check from a computer: nslookup firewall.lan.nexwall.com.br 192.168.1.1 must answer 192.168.1.1.

Good to know​

  • Every unit has a different certificate and key. A factory reset (or reinstall) makes a new key and a new certificate request.
  • The certificates are issued by Let's Encrypt; the names firewall.lan.nexwall.com.br and the serial name are public names in the certificate transparency logs (they contain the serial number of the unit, no other data).
  • Older firmware (up to 26.0.0-rc3): https://firewall.nexwall.com.br with one shared certificate, nothing to configure. The newer firmware keeps using it only as a fallback.
